2. The Two Ways to List a Product

WhatsApp (via Meta's Cloud API) was the original plan, but Meta rejected the business verification needed to make it work — so it was removed from the project entirely. Telegram fully replaced it: it lists products AND carries every seller notification, at zero cost with no verification risk.

ChannelStatusUse it when
Telegram bot✅ Live, primary Always — it's the fastest, works from your phone, zero setup per item
Admin Upload page (/admin/products/new) ✅ Live, backup Telegram is down, or you want to carefully review every field before it goes live (Draft mode)

2.1 Telegram Bot — the main way you list products

Find your bot in Telegram (the one whose token is in TELEGRAM_BOT_TOKEN) and just message it.

To list ONE product with one photo:

  1. Open a chat with the bot in Telegram
  2. Send a photo, with a caption describing it (e.g. Red leather handbag ₦8,500, brand new)
  3. Wait a few seconds — the bot replies with a confirmation and a link to the live listing
  4. The product is published immediately (not a draft) — it's already live on the store

To list ONE product with MULTIPLE photos (an album):

  1. In Telegram, tap the photo icon and select several photos at once (this creates what Telegram calls an "album" / "media group")
  2. Only ONE of the photos needs a caption — Telegram lets you add a caption to the whole album, usually on the first photo you select
  3. Send them all together
  4. Wait a few seconds longer than for a single photo (the bot waits ~2 seconds after the last photo arrives to make sure it has them all) — then you get ONE confirmation message for ONE product, with all the photos attached
  5. Important: put your price and description details in the caption. If a photo arrives without ever getting a caption attached to the album, the AI only has the photo to go on and may not catch the price.
If you made a mistake (wrong price, name, etc.) after sending:
  • Do NOT edit the message/caption in Telegram — this does nothing. Telegram doesn't tell the bot when you edit a message, so the listing never updates.
  • Instead, send a brand new text message describing the fix. Examples: price 165000, change the price to ₦165,000, update the name to Samsung Galaxy Buds Pro, change category to Electronics.
  • This always applies to whichever product you listed most recently (regardless of whether it's still live, sold, or anything else).
  • The bot will ALWAYS reply — either confirming what it changed, or telling you it didn't understand and giving you an example of what to try. It is never silent.
  • If you need to fix something that ISN'T your most recent listing, use the Admin Dashboard → Edit instead (see Section 3).

To mark your most recent LIVE (available) product as sold:

  • Send the exact text SOLD (any case — sold, Sold, SOLD all work)
  • The bot replies confirming which product it marked sold

Things the Telegram bot does NOT do:

  • It can't tell you what your current listings are (no "list my products" command) — check the live site or the Admin Dashboard for that.
  • It can't delete a product — use the Admin Dashboard.
  • It can't mark a specific product as sold by name if you've listed several since — SOLD always targets the most recent available one.

2.2 Admin Upload Page — the backup way, with more control

Go to /admin → log in → Add Product.

  1. Tap to take a photo, or pick from your gallery — or tap "pick from your image library" to reuse a photo you've already uploaded for a different product
  2. Wait while the AI reads it (spinner shown)
  3. Review the pre-filled fields — name, price + currency (NGN/USD), category, description — edit anything that's wrong
  4. Optionally add up to 5 more photos (tap + to upload a new one, or the grid icon to pick from your library) — only the FIRST photo gets read by the AI; extra photos are just stored
  5. Choose:
    • Save as Draft — saved but invisible to customers, until you publish it later
    • Publish Now — goes live immediately
This is the only channel that supports Draft mode (review before going live). Telegram listings always publish immediately.

3. Managing Products — the Admin Dashboard

Go to /admin/dashboard (log in first if needed).

3.1 What you see

  • Stats row: count of Live / Drafts / Sold products
  • + Add Product button → takes you to the upload page (Section 2.2)
  • Three tabs: Live, Drafts, Sold — each lists the matching products

3.2 Actions available per product, by status

StatusButtons availableWhat each does
DraftEdit, 🚀 Publish, Delete Publish makes it instantly visible on the store
LiveEdit, Unpublish, Mark Sold, Copy URL, Delete Unpublish sends it back to Drafts (invisible to customers, but not deleted)
SoldEdit, Re-list, Delete Re-list sets status back to Live/available
  • Edit → opens a full-page editor where you can change name, price, currency, category, description, and add/remove/reorder photos (same photo tools as the upload page — new upload, or pick from your image library)
  • Delete → permanent. Asks for confirmation first. Cannot be undone.
  • Copy URL → copies the public product page link to your clipboard, ready to paste anywhere (e.g. to share directly with a buyer)

3.3 How fast do changes appear on the live store?

Instantly. Every admin action (publish, edit, delete, status change) immediately tells the live site to refresh that page — you don't need to wait or do anything extra. (Telegram listings/edits do the same.) There's a 10-minute fallback refresh in case that instant signal is ever missed, but in practice you should see changes appear right away.

4. What Customers See and Can Do

4.1 Browsing the storefront

  • Category filter — pills along the top: All, Fashion, Electronics, Food & Drinks, Beauty, Home & Living, Other
  • Live search — typing in the search box filters the grid as they type (no page reload), searching by product name
  • Dark mode toggle — a small sun/moon button in the header. Switches the whole site to a dark color theme. Their choice is remembered on their device for next time.

4.2 On a product page

  • Photo gallery — large image with a thumbnail strip if there are multiple photos
  • Like (heart icon) and Save (bookmark icon) — these notify you (see Section 5)
  • "Request to Buy" button — opens a form where the customer enters their name, phone number, and an optional message. Submitting this saves their contact details, notifies you immediately, and shows the customer a confirmation that you'll reach out
  • Chat bubble icon — opens the Tawk.to live chat widget for general questions (separate from the Request to Buy flow)
  • SOLD overlay — if you've marked the item sold, the page still works (doesn't 404) but shows a "This item has been sold" message instead of the buy button

4.3 What customers can't do

  • They cannot see Draft products at all (the page returns "not found")
  • They cannot edit, delete, or directly negotiate a price through the site — that all happens via the Request to Buy form or the chat widget, with you replying personally

5. Notifications — what tells you something happened, and how

Every notification goes through one channel: Telegram, the same chat the bot lists products in.

EventNotified viaNote
New product listed (Telegram)Telegram message, same chatIncludes name, price, link
New product listed (Admin Upload, published)(none — you just did it yourself)
Someone likes a productTelegram message
Someone saves a productTelegram message
Someone submits a "Request to Buy"Telegram messageIncludes buyer's name, phone, and optional message
Someone marks SOLD via TelegramTelegram messageConfirms which product
Someone sends a free-text edit instructionTelegram messageConfirms the change, or explains it didn't understand

Views (just looking at a product) are never notified — only likes, saves, and buy requests.

7. Environment Variables — what they're for

These are the secret settings that connect the code to the services above. Actual current values live in .env.local (on this computer, never committed to GitHub) and must be duplicated in the Vercel dashboard (Settings → Environment Variables) for the live site to work. See CLAUDE.md for the exact current values.

VariableWhat it's for
NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEYDatabase connection
CLOUDINARY_CLOUD_NAME, CLOUDINARY_API_KEY, CLOUDINARY_API_SECRETPhoto storage
GEMINI_API_KEYAI photo/text reading
TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_IDThe Telegram bot's identity and where it sends you every notification
NEXT_PUBLIC_STORE_NAMEShown as the site title
NEXT_PUBLIC_SITE_URLUsed to build links sent in notifications
NEXT_PUBLIC_TAWKTO_IDConnects the live chat widget to your Tawk.to account
ADMIN_PASSWORDThe password for /admin
Gotcha to remember: if any value contains a # character (like a password), it MUST be wrapped in quotes in .env.local — e.g. ADMIN_PASSWORD="abc#123" — otherwise everything after the # is silently cut off when the site loads locally. This already happened once (see Section 8). Vercel's own dashboard doesn't have this problem; it only affects local testing on your computer.

9. Local Development & Deployment — for whoever is coding on this

# Install dependencies (first time only)
npm install

# Run locally
npm run dev
# → http://localhost:3000

# Check for type errors before trusting a change
npx tsc --noEmit

# Build exactly as production would
npm run build

# Commit and deploy
git add <files>
git commit -m "..."
git push          # Vercel auto-deploys main on every push

Before any major change, create a snapshot branch first (this project's convention):

git checkout -b snapshot-vN-description
git push origin snapshot-vN-description
git checkout main

At the start of any work session, confirm accounts are correct:

gh auth status                   # should show FAIT-Pro as active
gh auth switch --user FAIT-Pro   # if not
vercel whoami                    # often wrong — known unresolved issue, ignore and use git push

10. The Database, Simplified

Four tables, all in Supabase:

  • products — every item ever listed. status is one of available (live), draft, or sold. image_urls holds ALL photos for multi-photo items; image_url is just the first one, kept for backward compatibility. wa_message_id is how the system avoids creating a duplicate product if a webhook delivery repeats itself.
  • interactions — a log of every view/like/save/enquiry, used to power notifications and could be used for analytics later.
  • enquiries — every "Request to Buy" submission, with the buyer's name, phone, and optional message.
  • telegram_media_groups — a short-lived technical table that temporarily holds photos from a Telegram album while they're still arriving, before they get merged into one product. You'll never need to look at this directly; it cleans itself up automatically.

11. Glossary

TermMeaning
DraftA product saved but not visible to customers yet
Live / AvailableVisible to customers, can be bought
SoldNo longer for sale; page still loads but shows a SOLD badge instead of the buy button
WebhookA URL that another service (Telegram) calls automatically when something happens, e.g. when you send the bot a photo
Media group / albumTelegram's term for several photos sent together in one go
RLS (Row Level Security)A database rule that controls who can see what — e.g. customers can only ever see available products, never drafts
RevalidateThe mechanism that makes the live site update instantly after an admin action, instead of waiting for a scheduled refresh
Env var (environment variable)A secret setting (like a password or API key) kept outside the code, in .env.local locally and the Vercel dashboard in production
DeployPublishing a code change so it's live on the real website
Snapshot branchA saved copy of the code at a point in time, used as a safety net before risky changes
